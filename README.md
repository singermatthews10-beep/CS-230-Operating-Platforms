# CS 230 – Operating Platforms
## The Gaming Room: Draw It or Lose It
**Christopher Walker**

### 1. Briefly summarize The Gaming Room client and their software requirements.

The Gaming Room was a client that wanted to expand its existing Android game, Draw It or Lose It, into a web-based application that could run across multiple operating systems. The game involves teams competing to guess images as they are gradually revealed. The client needed software that could support multiple teams and players, maintain unique game and team names, and work across Windows, macOS, Linux, and mobile devices.

### 2. What did you do particularly well in developing this documentation?

I believe I did particularly well in organizing the software requirements and comparing different operating platforms. I evaluated the advantages and disadvantages of Windows, Linux, macOS, and mobile devices while considering performance, security, and compatibility. I also explained how object-oriented programming concepts, such as inheritance, encapsulation, and the Singleton design pattern, could help create an organized and maintainable application.

### 3. What about the process of working through a design document did you find helpful when developing the code?

Creating the software design document helped me understand why planning is important before writing code. Breaking down the requirements and identifying the relationships between classes made it easier to understand how the application should function. The UML class diagram was especially helpful because it showed how the Game, Team, and Player classes work together. This experience taught me that good documentation can make coding, troubleshooting, and future improvements easier.

### 4. If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

If I could revise one section, I would improve the system architecture documentation. I would add a more detailed diagram illustrating how client devices communicate with the application server and database. I would also expand the explanation of how the system handles network interruptions, performance issues, and increased numbers of users. These improvements would make the documentation more useful for developers responsible for implementing the application.

### 5. How did you interpret the user's needs and implement them into your software design? Why is it important to consider the user's needs when designing?

I interpreted the client's needs by reviewing the software requirements and identifying the features necessary for the application to function across multiple platforms. For example, I recommended a web-based architecture so users could access the game without needing a separate application for every operating system. I also considered security, unique identifiers, and reliable data management. Understanding user needs is important because software should solve real problems while providing a positive user experience.

### 6. How did you approach designing software? What techniques or strategies would you use in the future?

I approached software design by first understanding the client's requirements and evaluating the technical challenges involved. I compared operating systems, reviewed architecture options, and considered storage, memory management, networking, and security. I also used object-oriented programming principles and UML diagrams to organize the application. In future projects, I plan to continue using requirements analysis, design diagrams, and thorough documentation before writing code. I would also seek regular feedback and incorporate testing early in development to ensure the software meets user expectations.
